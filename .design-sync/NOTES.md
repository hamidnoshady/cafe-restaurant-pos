# design-sync notes — cafe-restaurant-pos

Repo-specific gotchas for future syncs. This is a **package-shape** sync of an in-repo
shadcn/ui component set (`src/components/ui/*`), not a published library.

## Setup / build

- **No `dist/` and the package isn't published.** The converter runs in **synth-entry mode**
  (`[NO_DIST]` is expected, not an error): it synthesizes the bundle entry from
  `src/components/ui/*.tsx`. `cfg.srcDir` scopes discovery to that dir so app pages
  (`src/app/**`) don't leak in as components.
- **PKG_DIR symlink is required.** The converter resolves the package at
  `node_modules/<pkg>`, which npm won't self-install. Before building, recreate:
  `ln -sfn "$(pwd)" node_modules/cafe-restaurant-pos`. It's a gitignored, per-clone step.
- **Tailwind v4 CSS must be compiled.** The utility classes the components use
  (`bg-primary`, `h-8`, …) are generated by Tailwind at build time; the raw
  `src/app/globals.css` only holds `@import "tailwindcss"` + `@theme` tokens. `cfg.buildCmd`
  = `node .design-sync/compile-css.mjs` compiles them (via the repo's own
  `@tailwindcss/postcss`) to `.design-sync/.cache/compiled.css`, which `cfg.cssEntry` points
  at. **Always run buildCmd before the converter** (the cache is gitignored, so a fresh
  clone must regenerate it).
- **Vazirmatn font is inlined.** The app serves it via `next/font/local` at runtime, which
  the bundle can't do. `compile-css.mjs` inlines `src/app/fonts/Vazirmatn-Variable.woff2`
  as a **data-URI @font-face** (unquoted `url(data:…)` — a quoted data-URI trips the
  converter's dead-@font-face drop heuristic in `lib/css.mjs`) and defines
  `--font-vazirmatn: "Vazirmatn"` so the tokens' font stack resolves.
- **Playwright:** the render check needs `playwright@1.56.0` (pins chromium build 1194,
  which is the pre-installed browser at `/opt/pw-browsers`). Install into `.ds-sync/`.

## Component scoping

- 19 primary components are carded (Alert, Badge, Button, Card, Checkbox, Dialog,
  DropdownMenu, Field, Input, Label, RadioGroup, Select, Separator, Skeleton, Switch,
  Table, Tabs, Toaster, Tooltip). Their **sub-parts** (CardHeader, TableRow, DialogContent,
  SelectItem, …) are excluded from the card list via `componentSrcMap: null` but remain
  fully importable from `window.CafePos` — previews compose them inside the parent.
- **In synth mode, `componentSrcMap` must contain ONLY `null` entries.** Any non-null
  (src-pin) entry makes the discovered-names set non-empty, which bypasses the
  synth-from-src fallback entirely and you end up with just that one component. So no
  src-path pins here (Toaster is discovered from `sonner.tsx` without enrichment — fine).
- **`.d.ts` props are hand-written** in `cfg.dtsPropsFor` (synth mode extracts no props —
  they'd be `[key: string]: unknown`). Curated per-component bodies capture the
  DS-specific props (variant/size unions, Radix control props). If a component's source API
  changes, update its `dtsPropsFor` entry.

## Previews

- All 18 non-Toaster components have authored previews in `.design-sync/previews/`, using
  realistic **Persian POS content** (café/restaurant labels, Toman prices in Persian
  digits) wrapped in `dir="rtl"` — this is the true rendering context and exercises the
  Vazirmatn font + RTL layout.
- **Overlay components** (Dialog, DropdownMenu, Select, Tooltip) use `open`/`defaultOpen`
  and `cfg.overrides.<Name> = {cardMode: "single", primaryStory, viewport}` so the open
  (portaled) state renders in-card without a fixed overlay covering sibling stories.
- Icons come from `lucide-react` (bundled into the preview, not in `window.CafePos`).

## Known render warns

- None outstanding. `Toaster` renders the **floor card by design** — sonner toasts are
  imperative/interaction-driven and can't render statically (authoring it would be a
  hand-drawn lookalike). It is fully importable; author it later only if a static
  representation becomes worthwhile.

## Re-sync risks (what can silently go stale)

- **`compile-css.mjs` inlines a specific font file and defines `--font-vazirmatn`.** If the
  brand font changes or the token stack in `globals.css` renames the variable, the inline
  block in `compile-css.mjs` needs updating.
- **`dtsPropsFor` is a hand-maintained snapshot** of the component APIs as of this sync. It
  does not auto-track source changes — re-check against `src/components/ui/*.tsx` on a
  re-sync if components were edited.
- **The compiled CSS is content-detected by Tailwind over the whole repo.** If a component
  starts using a utility only referenced elsewhere (or nowhere), it could be pruned. Every
  class the ui components use is currently emitted because Tailwind scans `src/`.
- The `node_modules/cafe-restaurant-pos` symlink and `.design-sync/.cache/compiled.css` are
  gitignored and must be regenerated on a fresh clone (symlink + `buildCmd`).
